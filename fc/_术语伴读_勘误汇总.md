# 术语伴读勘误汇总

写这份术语伴读系列时，为了讲清「它为什么长这样」，每个断言都重新核了一遍代码与手册。
**结果是查出了一批原有的错误说法**，其中有文档错误，也有**代码注释错误**。
这份文件把它们集中到一处，方便你一次看完。

> **重要前提**：所有修正**只改注释与文档，没有改任何一行代码逻辑**。
> 每个改过的文件都用「剥离注释后哈希比对」验证过，且固件重新构建后
> **FLASH 63116 B / RAM 5136 B 与改动前完全相同**。

## 一、影响最大的四条（会误导判断的）

| # | 错误说法 | 事实 | 为什么影响大 |
| --- | --- | --- | --- |
| 1 | 「`flight_ctrl()` 每 1ms 执行一次，由 TIM17 中断调用」（**7 处注释 + 手册**都这么写） | 唯一调用点是 `user/main.c:410`，**在主循环**；TIM17 中断只做计数自增（`bsp_timer.c:168-194`） | 1ms 是**时基**节拍，不是控制环周期。混淆会让「PID 按多快调」「滤波器系数按什么采样率算」全盘偏移。实测主循环一圈约 **4.6ms**（`main.c:407` 标 2.1~3.9ms + `main.c:410` 标 2.5~3.4ms） |
| 2 | PWM 频率按 **24MHz** 基数算（`bsp_pwm.c`/`led.c`/`led.h`/`spi.c` 共 9 处） | `main.c:165-166` 的 AHB/APB1 都是 **DIV1** ⇒ 基数是 **48MHz**。故 TIM3 = **16kHz**（原写 10kHz）、TIM1 = **20kHz**（原写 10kHz）、SPI1 = **1.5MHz**（原写 750kHz） | 电调 PWM 频率直接影响电机驱动是否正常（太低会啸叫抖动、太高部分电调不认） |
| 3 | GPIOA 基地址写成 `0x40000000`（4 处） | 手册表 3-2：**GPIOA = `0x5000 0000`**（IOPORT 区）；`0x4000 0000` 是 **APB 区** | 注释里的「真机写法」若被照抄，在真机上会操作到**别外设** |
| 4 | 对码时「`ch_change_arr` 两个元素都是 36，并未跳频」 | `main.c:265` 把 `[1]` 赋成 `pair_data.rf_ch`，而**此时 `flash_read()`（328 行）还没执行**⇒ `pair_data` 零初始化 ⇒ 实际是 **`{36, 0}`**，在 **2436MHz 与 2400MHz** 间扫描 | 影响对「对码为什么会成功」的理解，也影响改信道时的判断 |

## 四、新增的记录（不是错误，是查出来的事实）

- **11 条「注释数值与代码不符」**（如注释说 256、代码是 512；注释 α=0.7、代码 0.1）—— 见手册 11.5 节 A 组
- **2 处参数与假设矛盾**：ODR 配 200Hz 但滤波器按 800Hz 设计；串级 PID 内外环量纲不一致 —— 见手册 11.5 节 B 组
- **「实现了但没调用」两处**：陷波器（`filter.c:160-169`）、`calGyroVariance()`（`imu.c:29-71`）
- **本工程实际用的滤波与姿态算法总表**（带行号）—— 见手册 11.5 节 D 组

## 五、怎么自己复核

```powershell
# 1) 看三批发现的原始记录（含逐条依据）
#    术语解析手册.md 的 11.4 / 11.5 / 11.6 节

# 2) 看每份伴读自己的勘误节
#    术语伴读01-03 的第 5 节；术语伴读04-06 / 07-08 的附录；飞控技术演进总纲 8.1 节

# 3) 重新核验「只改注释、未动代码」
#    各修正脚本都在 build-gcc\tools\ 下，脚本里记录了改动前的哈希
```

> **一个值得注意的规律**：这套伴读系列一共触发了 **三次**「写伴读反而查出正文错误」
> （C/C++ 教程 16 处、术语手册第一批 6 处 + 总纲 5 处 + 01-03 一批）。
> 原因不难理解：**写「为什么」时必须把每个断言重新核一遍，
> 而写「是什么」时容易照着已有说法抄。**
> 所以伴读的价值不只是「讲清来龙去脉」，它同时起到**审计**作用。
