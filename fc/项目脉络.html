一、全景：两个工程、四层结构#

示意图
  ┌──────────────────────────────────────────────────────────────┐
  │  遥控器（发射端）                                             │
  │    摇杆/按键 → joystick.c → deal_data.c 组包 → PN298 2.4G    │
  └───────────────────────────┬──────────────────────────────────┘
                              │ 12 字节上行包（0xAA 指令 / 0xDB 对码）
                              │ 12 字节下行 ACK 载荷（遥测/低压标志）
                              ▼
  ┌──────────────────────────────────────────────────────────────┐
  │  飞控（飞机）                                                 │
  │                                                              │
  │  第4层 应用    user/main.c        初始化顺序 + 主循环调度      │

  │  第2层 算法    imu/imu.c          姿态解算（Mahony）          │
  │                imu/pid.c          姿态控制（角度→角速度→混控）│
  │                imu/altitude.c     高度融合 + 定高             │

一句话：遥控器把摇杆变成 12 字节射频包；飞控收到后解成内部指令， 读传感器算出姿态，用 PID 算出四个电机该转多快，再回一个 ACK 给对方。

四、主循环怎么调度（理解整个飞控的关键）#

main.c 本体只是调度器：TIM17 每 1ms 给几个计数器 +1，主循环比对阈值决定该谁干活。

触发条件实际周期跑什么文件
_cnt10ms >= 10约 11msdecode_pack() 收遥控 + annexCode() 换算指令user/deal_pack.c、imu/decode.c
_cnt4ms >= 4约 5msMode_Controler() 空翻状态机user/flip.c
每一圈约 4.6msaltitude_ctrl()（定高）+ flight_ctrl()（姿态控制）imu/altitude.c、imu/fc.c
_cnt100ms >= 100约 101ms喂狗 + Led_Process() 刷灯user/WDG.c、user/led.c
_cnt1s >= 1000约 1.001sget_voltage() 读电池user/adc.c
每一圈—失联检测（>5000ms 没收到包 → 自动降落）main.c:470
每一圈—油门低位且飞机平放 → 自动解锁main.c:432-448

⚠ 两条最容易看错的地方#

  1. 控制环不在 1ms 中断里，而在主循环。 TIM17 中断（drivers/bsp/bsp_timer.c）

只做计数器自增；flight_ctrl() 的唯一调用点是 main.c:410。 1ms 是时基，不是控制周期 —— 实测主循环一圈约 4.6ms。 （工程里有 7 处注释曾写成「在 TIM17 中断里」，已更正。）

  1. 周期实际是 N+1 ms。 判断是「先比较后清零」，而中断在同一毫秒内还会 +1，

所以 _cnt4ms>=4 实际约 5ms、_cnt100ms>=100 实际约 101ms。

八、建议的读代码路线#

按「从外到内」的顺序，每一步都能独立看懂：

  1. user/main.c —— 先用第三节的时序表对着读，明白「上电先干什么」。
  2. user/main.c:379 的主循环 —— 明白任务是按计数器分派的，以及周期是 4.6ms 而不是 1ms。
  3. user/deal_pack.c —— 一个 12 字节包怎么变成 fcCmd[]。这里能看懂通信协议。
  4. imu/decode.c —— fcCmd[] 怎么变成 rcCommand[]（指令的含义在这一层变化）。
  5. imu/fc.c —— 状态机（解锁/起飞/降落）+ 它按什么顺序调下面三个。
  6. imu/imu.c —— 传感器数据怎么变成姿态角（Mahony 互补滤波）。
  7. imu/pid.c —— 姿态角怎么变成四个电机的占空比（角度环→角速度环→混控）。
  8. imu/altitude.c —— 高度怎么融合、定高怎么叠加到油门。
  9. user/WDG.c + user/led.c —— 安全与提示（看门狗、灯语）。

为什么按这个顺序：1~2 建立「程序骨架」，3~5 建立「数据怎么进来、 状态怎么管」，6~8 才是算法。先骨架后算法，读起来不容易迷路。
