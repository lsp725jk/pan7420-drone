飞控代码注释规范

给代码写注释的格式、深度要求与纪律
PAN 飞控工程 · PY32F030 (Cortex-M0+) · 由 build-gcc/tools/md_to_html.py 生成

给 飞控/ 下所有 .c / .h 加中文注释时，必须遵守本规范。 目标读者：能写代码、但没写过飞控的嵌入式学习者。所以注释要讲"为什么"，不能只讲"是什么"。

一、每个文件必须有文件头块#

放在文件最顶端（若已有版权头，放在版权头之后），格式如下：

示意图 · c
/* ============================================================================
 * 文件：imu/pid.c                     【角色】姿态控制的核心算法
 * ----------------------------------------------------------------------------
 * 一、这个文件在项目里干什么
 *     （2~4 句。说清它在数据流里的位置：谁给它输入、它算出什么、给谁用）
 *
 * 二、它在整个飞控里的位置（数据流）
 *     加速度计/陀螺仪 → accgyro.c（校准、去零偏）
 *                     → imu.c（姿态解算，得到角度）
 *                     → pid.c（本文件：算出电机修正量）
 *                     → bsp_pwm.c（输出 PWM 给电调）
 *
 * 三、关键设计取舍（为什么这样写）
 *     （1~3 条。例如：为什么用整数定点而不是浮点、为什么放在定时中断里）
 *
 * 四、对外接口（被谁调用）
 *     - pidInit()        ：fc.c 初始化时调用
 *     - pidUpdate()      ：main.c 的 1kHz 循环里调用
 *     - pidReset()       ：解锁/上锁时调用
 * ==========================================================================*/

二、函数注释：四要素#

每个函数（含 static）上方都要有：

c
1/**
2 * @brief  一句话说明这个函数做什么
3 *
4 * 【参数】
5 *   @param err   本次角度误差（单位 0.1 度，int16_t）
6 *   @param dt_ms 距上次调用的时间（毫秒）
7 *
8 * 【返回】 电机修正量（-500~500，占空比千分比）
9 *
10 * 【算法】为什么这么算
11 *   标准位置式 PID：out = Kp*e + Ki*∫e + Kd*de/dt
12 *   这里做了两处针对本项目的改动：
13 *     1) 积分项加了限幅（anti-windup）—— 否则长时间偏差会让积分饱和，
14 *        反向修正时"甩不回来"，表现为打舵迟钝；
15 *     2) 微分项对测量值求导而不是对误差求导 —— 避免设定值突变时
16 *        微分项产生尖峰（derivative kick）。
17 *
18 * 【调用关系】
19 *   被 imu.c: imuCalculateEstimatedAttitude() 每 1ms 调用一次。
20 *   它依赖 mlib.c 的 mlib_abs() 做死区判断。
21 *
22 * 【注意】 必须放在定时中断里调用；在主循环里调用会因周期抖动导致 D 项噪声。
23 */

三、讲清"关联"与"为什么"的三类行内注释#

  1. 跨文件关联：调用别人 / 被别人调用时注明来源

``c accgyro.gyroADC[axis] = ...; /* 原始 ADC → accgyro.c 的校准流程会减掉零偏 */ ``

  1. 算法步骤：分步骤标注，让人能对着公式看代码

``c /* 步骤 2：四元数微分方程 q' = 0.5 * q ⊗ ω ， 这里用一阶欧拉积分近似，dt 固定为 1ms 所以把 dt 折进系数里 */ ``

  1. 魔法数字 / 硬件相关常量：必须解释来源

``c #define GYRO_CALI_DIFF_LIMIT 40 /* 静止判定阈值：实测静止时陀螺仪抖动 <20，取 2 倍余量 */ ``

用户明确要求：语法的关键字、用法及变式都要说明。

4.0 英文缩写必须配中文说明（用户明确要求）#

规则：注释里出现英文缩写时，第一次出现必须在旁边写中文意思。

写法（把中文放在缩写后面）：

c
1/* 好：缩写后面直接跟中文 */
2/* ODR（输出数据速率）设为 1kHz */
3/* 通过 SPI（串行外设接口）读 ICM42688（6 轴惯性测量单元） */
4 
5/* 不好：光写缩写，读者得另外去查 */
6/* ODR 设为 1kHz */
7/* 通过 SPI 读 ICM42688 */

哪些要加：所有非"人人皆知"的缩写。完整清单见 术语解析手册.md 第 12 节 英文缩写速查表（按芯片内核 / 外设通信 / 传感器姿态 / 飞控业务 / 工具链 / 常用英文术语 分六类，每项含英文全称与中文说明）。

哪些可以不加：

  • LED、USB、CPU 这类日常到不需要解释的；
  • 同一个文件内已经在前面解释过的缩写（讲过一次就够了，不必每行重复）。

为什么这条重要：本工程横跨射频、传感器、编译器工具链多个领域，缩写密度很高 （工具统计下来光官方文档里就有 800 多种大写缩写）。对"很久没接触嵌入式"的读者， ODR、FSR、NVM、IWDG 这类词光看英文完全想不起来是什么。 加一个中文说明的成本极低，收益很大。

4.1 总原则#

遇到关键字/特殊语法，就用 1~4 行注释讲清三件事：

  1. 它在这里起什么作用（不是抄语法书的定义，而是"为什么这里需要它"）；
  2. 有什么变式（同一种写法在别处会怎么变，容易搞混的对比）；
  3. 有什么坑（用错了会怎样）。

完整的关键字教学见同目录 C_KEYWORDS_GUIDE.md（14 节，含本工程真实实例）。 在代码里遇到时，用一行注释指过去即可，例如： ``c static float rate_i[3]; /* static 局部变量：跨调用保持。详见 C_KEYWORDS_GUIDE.md 第 1.4 节 */ `` 不要把整篇指南复制进代码 —— 文件头 + 关键点用一两句话点到即可。

4.2 必须讲的关键字（按本工程出现频次排序）#

优先级关键字/写法必须讲清的点
★★★static三种含义（文件内全局/文件内函数/函数内保持状态）——最易混，务必分开讲
★★★volatile为什么中断共享变量必须加；它不保证原子性
★★★位运算 `\= &= ^= << &(1<<n)`为什么用 `\= 而不是 =`（会清掉别人配的位）
★★★强制类型转换 (uint16_t)窄化/符号变化风险：负数转无符号会回绕成巨大值
★★☆const修饰变量 vs 修饰指针（const char* 与 char* const 的区别）
★★☆extern声明 vs 定义的区别；局部 extern 的隐患
★★☆typedef / struct / enum别名用法；_s/_e/_t 命名约定
★★☆位域 :1省 RAM 的用途；不能取地址、布局依赖编译器
★★☆宏 #define参数加括号的原因；多语句宏为何要 do{}while(0)；副作用陷阱
★★☆条件编译 #if defined(...)本工程用它同时支持 ARMCC 与 GCC
★☆☆union内存重叠；字节序（M0+ 是小端）
★☆☆inline / static inline只是建议；与宏的取舍
★☆☆__weak弱符号机制（库给默认实现，工程覆盖）
★☆☆__attribute__((naked/packed))用途与风险（packed 后未对齐访问会 HardFault）
★☆☆switch / do-while / gotobreak 贯穿、default 必要性、goto 只用于统一清理
★☆☆sizeof / 数组退化数组传参后退化成指针，必须另传长度
★☆☆ISR 写法函数名由向量表决定；短、不阻塞；"中断打标记、主循环干活"

4.3 相对旧版第四节的说明#

下面这张表是精简版，详细讲解一律看 C_KEYWORDS_GUIDE.md：

写法一句话要点
volatile中断与主循环共享的变量必须加，编译器不能缓存到寄存器
__weak弱符号：库里给默认实现，工程里重定义即可覆盖（如中断服务函数）
static函数外用=文件内可见；函数内用=跨调用保持状态
__attribute__((packed))结构体不填充对齐字节；但成员可能未对齐，M0+ 上直接访问会异常
位域 a:1紧凑存布尔标志，省 RAM（8KB 很紧张）；但不能取地址
定点数（>> 30 之类）为什么不用 float：M0+ 没有 FPU，软浮点慢且占 Flash
中断服务函数必须短、不能阻塞、共享变量要 volatile

五、改动纪律（很重要）#

  1. 只加注释，不改任何代码逻辑。哪怕看到疑似 bug，也只在注释里写

/* 注意：这里疑似……，未改动 */，不要动代码。

  1. 注释用简体中文，术语首次出现给英文原文，例如"姿态解算（attitude estimation）"。
  2. 保持文件原有缩进与风格；不要重排代码、不要改行尾。
  3. 文件已是 UTF-8 with BOM，用 UTF-8 保存即可，不要改成其他编码。
  4. 不要删除或改写作者原有的中文注释 —— 它们是作者自己的记录，可以在其后补充说明。
  5. 篇幅要求：宁详勿略。核心算法文件（imu/、ctl/）注释量可到代码量的 1~2 倍；

厂商驱动（icm426/、bmp3）只在文件头和关键函数上写，不做逐行。
