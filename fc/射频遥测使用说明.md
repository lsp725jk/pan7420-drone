# 射频遥测使用说明（飞行时在电脑上看姿态与状态）

> **这份文档回答**：怎么让飞机在飞行时把姿态和状态发到电脑上显示。
> 包含接线、开关、操作步骤、能看到什么、以及**精度与已知限制**。

---

## 一、先看数据是怎么走到电脑的

```
   ┌─────────────┐   PN298 2.4G（唯一无线通道）
   │  飞机        │ ──────────────────────────────►  ┌──────────┐
   │ imu/        │   遥测帧搭在 ACK 载荷里回传         │  遥控器   │
   │ rf_telemetry│   （12 字节，用 [2..11]）           │ 转发      │
   └─────────────┘                                    └────┬─────┘
                                                          │ USART2
                                                          │ 有线（遥控器拿在手上，线不碍事）
                                                          ▼
                                                    ┌──────────┐
                                                    │ USB-TTL  │
                                                    └────┬─────┘
                                                         ▼
                                                    ┌──────────┐
                                                    │  电脑     │
                                                    │ 曲线显示  │
                                                    └──────────┘
```

**为什么必须绕这一圈**：飞机上有串口，但飞行中不能拉线（会被扯断、接头会松）。
所以飞机的串口只能用于**地面调试**；飞行时只能靠射频。而射频的"飞机 → 遥控器"
通道本来就有（ACK 应答），我们把遥测数据搭在它上面就行。

---

## 二、需要买什么（你目前没有硬件）

| 物品 | 说明 | 参考价 |
| --- | --- | --- |
| **USB-TTL 转接器** | CH340 / CP2102 / FT232 都行，**要 3.3V 电平**的 | 5~15 元 |
| 杜邦线 3 根 | 接 TX / GND（见下方接线） | — |
| （可选）焊接工具 | 如果遥控器板上没引出排针 | — |

> **一定要用 3.3V 的转接器**。PY32F030 是 3.3V 芯片，
> 5V 电平长期接上去可能损坏引脚。多数 CH340 模块有 3.3V/5V 跳线，选 3.3V。

---

## 三、接线

### 遥控器侧（这是要接到电脑的那一端）

| 遥控器引脚 | 接到 USB-TTL |
| --- | --- |
| **USART2_TX = GPIO_PIN_4** | → 转接器的 **RXD** |
| **GND** | → 转接器的 **GND** |

依据：`遥控器/user_driver/bsp_uart.c:17` 定义 `UARTx_TX_PIN = GPIO_PIN_4`，
`:14` 定义 `UARTx = USART2`，`:15` 波特率 **115200**。

> ⚠ **只接 TX 和 GND 就够**（单向，电脑只收）。不要接 5V/3.3V 电源线 ——
> 遥控器自己有电池，接了反而可能产生电源冲突。

### 飞机侧（仅地面调试用）

飞控的调试串口是 **USART1：TX = PB8、RX = PB2，115200 8N1**
（依据：`飞控/drivers/bsp/bsp_uart.c:75-77`）。

地面调试时：**PB8 → USB-TTL 的 RXD**，**GND → GND**。
此时不用管遥控器，直接看飞机自己 `printf` 的内容。

## 四、打开两个开关（默认都是关的）

代码里的遥测功能**默认关闭**，所以现在的固件行为与你改动前**完全一致**。
要用就得打开两个开关：

| 位置 | 开关 | 改成 |
| --- | --- | --- |
| `飞控/imu/rf_telemetry.h` | `#define RF_TELEMETRY_ENABLE   0` | **1** |
| `遥控器/user/main.c` | `#define RC_TELEMETRY_FORWARD_ENABLE   0` | **1** |

然后：

- **飞机**：用 `build-gcc\build-gcc.ps1 -Project fc` 重新编译烧录（已经验证可编译，占 **528 字节 Flash**）
- **遥控器**：用 MDK-ARM（Keil）重新编译烧录

> **为什么要两个开关**：飞机负责"打包进 ACK"，遥控器负责"从串口转发"。
> 只开一个都不会有数据 —— 这是排查时最该先确认的地方。

## 五、电脑侧操作

### 1) 装依赖

```powershell
pip install pyserial
# 想要图形显示再加：
pip install matplotlib
```

### 2) 先看串口有没有

```powershell
python build-gcc\tools\telemetry_view.py --list
```

### 3) 纯文本模式（**先用这个确认通了**）

```powershell
python build-gcc\tools\telemetry_view.py COM5
```

正常的话每 0.5 秒会滚出这样一行：

```
横滚角=1.23 | 俯仰角=-0.45 | 偏航角=89.01 | 电池电压=3.85 | ...
   状态: 已解锁   收帧=248 坏CRC=0 丢帧≈3
```

**"坏CRC=0、收帧不断增长"就说明链路通了。**
如果一直是 `收帧=0`，按第六节排查。

### 4) 图形模式

```powershell
python build-gcc\tools\telemetry_view.py COM5 --plot
```

会画出**姿态角曲线**和**四个电机输出曲线**两张图，实时滚动。

### 5) 存 CSV 事后分析

```powershell
python build-gcc\tools\telemetry_view.py COM5 --csv run.csv
```

## 六、能看到哪些数据

遥测帧只有 10 字节，装不下所有量，所以**按组轮转发送**（约 50Hz 发送，
12 组轮转 ⇒ 每个量约 4Hz 刷新）。

| 组 | 数据 | 单位 / 倍率 |
| --- | --- | --- |
| 0 | 横滚角、俯仰角 | 度（飞机侧是"度×100"，脚本已换算） |
| 1 | 偏航角、电池电压 | 度；伏 |
| 2 | 估计高度、定高 PID 输出 | 毫米；原始值 |
| 3 | 加速度 X、Y | g（1g = 4096 LSB） |
| 4 | 加速度 Z、平滑加速度 Z | g |
| 5 | 角速度 X、Y | 度/秒 |
| 6 | 角速度 Z、平滑加速度 X | 度/秒；g |
| 7 | 电机 0、1 | 千分比 0~1000 |
| 8 | 电机 2、3 | 千分比 0~1000 |
| 9 | 内部指令 横滚、俯仰 | -500~+500 |
| 10 | 内部指令 油门、偏航 | 1000~2000；-500~+500 |
| 11 | **状态标志位**、遥控原始横滚 | 位域；原值 |

**状态标志位含义**（组 11 的第 1 个数字）：

| 位 | 含义 |
| --- | --- |
| bit0 | 已解锁（motorArmed） |
| bit1 | 怠速（motorIdle） |
| bit2 | 起飞中 |
| bit3 | 降落中 |
| bit4 | 有新指令 |
| bit5 | 允许校准 |
| **bit9** | **失联**（超过 5 秒没收到有效遥控包） |
| **bit10** | **低电** |

脚本会直接把位域翻译成文字（"已解锁、失联"这样）。

## 七、精度与已知限制（**请务必读这一节**）

### 7.1 量化精度（实测）

| 量 | 精度 | 说明 |
| --- | --- | --- |
| 姿态角 | **0.01 度** | 不缩放，无损 |
| 加速度 | ±0.002 g | 右移 4 位（÷16） |
| 角速度 | ±0.12 度/秒 | 右移 2 位（÷4） |
| 高度 | ±8 毫米 | 右移 4 位（÷16） |
| 电机 / 指令 | 无损 | 量程本身就在 int16 内 |

**够用来**：看姿态对不对、看趋势、调参、判断失联/低电。

**不够用来**：分析传感器噪声、算振动频谱。
那需要原始 32 位值，请用**有线串口**或调试器看。

> 想提高角速度精度：把 `rf_telemetry.c` 的 `RF_TLM_SHIFT_GYRO` 从 2 改成 1
> （÷2），精度翻倍、范围仍达 ±4000°/s。**改完必须同步改**
> `telemetry_view.py` 里的倍率表，否则数字会错一倍。

### 7.2 刷新率限制

- 遥控器每 **50Hz** 发一次数据（`loop50HzFlag`），遥测搭在这个 ACK 上
- 12 组轮转 ⇒ **每个量约 4Hz 刷新**
- 姿态角的两个量在同一组，所以看到的姿态是 **4Hz 的完整快照**

对"看姿态"够用。**想更快**：把 `rf_telemetry.c` 的 `RF_TLM_GROUP_COUNT` 改小、
或让姿态组多轮几次（在 `rf_get_group` 的 switch 里给 case 0 多留几个组号）。

### 7.3 ⚠ 两端"字节编号"存在不一致（原有问题，未改动）

摸底时发现一处**原有**的不一致，与本次遥测无关，但你该知道：

- 飞机把**低电标记**写在 `temp_buff[1]`（`user/adc.c:245/254`，值 = 2）
- 遥控器读的是 `ack_buff[0]` 判断低电（`遥控器/user/main.c:243`，
  `deal_data.h:28` 的 `LOW_VOL = 2`）
- 而 `ack_buff[0]` 是**遥控器自己写进去的**对码标志（`遥控器/user/main.c:166`）

**下标差一位，所以遥控器的低压蜂鸣很可能不会响。**
本次**没有改动**它（避免影响未验证的原有行为）。遥测用的是 `[2..11]`，
与前两字节无关，所以**不影响遥测**。

如果你希望修这个，改法是把飞机侧的写入改成 `temp_buff[0]`，
或把遥控器的判断改成 `ack_buff[1]` —— 但**两者改动方向相反**，
必须先确认哪个字节约定才是设计意图（建议对照遥控器上低压提示的实际表现来定）。

### 7.4 其他限制

- **只在"正常模式"转发**。遥控器还有个 CRSF 模式（串口 400000 波特，
  给外置高频头用），那一路不转发遥测。
- **飞机侧 GCC 构建、遥控器侧 MDK 构建**：我只验证了飞机侧的编译
  （`build-gcc` 用的是 arm-none-eabi-gcc）。**遥控器侧改动未经编译验证** ——
  你那边用 Keil 编译时如果报错，把错误发我。
- **没有实测上机**：CRC 与倍率已做**端到端回环测试**（PC 上两端算法对拍，全部通过），
  但真实射频链路上的表现（丢包率、ACK 是否总能带回 12 字节）**需要你上机验证**。

## 八、排查：收不到数据怎么办

按这个顺序查（每步都能独立确认）：

| 步骤 | 怎么查 | 正常表现 |
| --- | --- | --- |
| 1 | 飞机侧开关开了吗？（`RF_TELEMETRY_ENABLE`） | 飞机固件里确实包含遥测代码 |
| 2 | 遥控器侧开关开了吗？（`RC_TELEMETRY_FORWARD_ENABLE`） | 遥控器会转发 |
| 3 | **用飞机侧有线串口**接电脑，看有没有 `printf` 输出 | 看到"对码成功"等文字 → 说明飞机在跑 |
| 4 | 遥控器串口接对了吗？TX(PIN_4) → **RXD**（不是 TXD） | 常见错误：TX 接 TX |
| 5 | 串口号选对了吗？被串口助手占用了吗？ | 关掉其他串口软件 |
| 6 | 遥控器**正常模式**吗？（不是 CRSF 模式） | 正常模式下才转发 |
| 7 | 拿 `--raw` 看原始十六进制 | 有 `5A ..` 开头 → 帧在，是解析问题 |

```powershell
python build-gcc\tools\telemetry_view.py COM5 --raw
```

**如果第 7 步看到 `5A` 开头的帧但脚本报 CRC 错**：说明飞机侧与电脑侧版本不一致
（比如你改了缩放常量但没同步脚本）。重跑一遍自检：

```powershell
python build-gcc\tools\test_telemetry_roundtrip3.py
```

它会**从飞机侧源文件直接读缩放常量**，然后对拍两端算法 —— 全部 ✅ 才算一致。
