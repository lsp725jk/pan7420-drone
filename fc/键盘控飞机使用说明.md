## 1. 数据是怎么走的

```
   电脑（pc_keycontrol.py 读键盘）
        │ 串口 115200（USB-TTL）
        ▼
   遥控器 USART2_RX = PB2
        │ rc_pc_ctrl.c 解析 → 覆盖 hardware_value[0..3]
        ▼
   遥控器原有打包逻辑 Send_Remote_Data()
        │ 2.4G 射频（PN298）—— 原有的上行包，格式不变
        ▼
   飞机 decode_pack() → fcCmd[] → 姿态/高度控制
```

**关键设计：飞机侧完全不用改。** 遥控器把键盘指令"冒充成摇杆值"塞进去，
飞机根本不知道你在用键盘。所以：

- 不动飞机固件
- 不动射频协议
- 不动飞控的控制逻辑

## 2. 键位

| 键 | 作用 | 松手后 |
| --- | --- | --- |
| **空格** | 上升 | **保持当前高度** |
| **左 Ctrl** | 下降 | **保持当前高度** |
| **W / S** | 前进 / 后退（机身倾斜） | 回中（但会带着速度继续飘） |
| **A / D** | 左移 / 右移（机身倾斜） | 同上 |
| **Q / E** | 机身左转 / 右转 | 停止旋转 |
| **B** | 紧急放松（立刻回中并取消接管） | — |
| **Ctrl + C** | 退出程序 | — |

### "松手保持高度"是怎么实现的

不是靠电脑记住高度，而是**利用了飞机已有的升降速度环**：

飞机侧 `imu/decode.c:56-76` 的逻辑是：

| 油门值 | 飞机的行为 |
| --- | --- |
| > 1550 | `setVelocity = (油门-1550)×4` → **上升** |
| < 1450 | `setVelocity = (油门-1450)×1` → **下降** |
| **1450~1550** | **`setVelocity = 0` → 速度环维持当前高度** |

所以**松手时程序发 1500**，正好落在保高区。这是飞控本来就有的能力，不需要新写代码。

**上升档位换算**（可以在命令行调）：

| 你设的 `--climb` | 油门值 | 飞机目标速度 |
| --- | --- | --- |
| 150（默认） | 1700 | +600 |
| 50 | 1600 | +200（更温和） |
| 400 | 1950 | +1600（较快） |

**下降档位**同理：`--descend 300` → 油门 1150 → 速度 -300。

### WASD 的"倾斜"有多大

飞机侧 `pid.c:260`：`target_angle = 20 × rcCommand`，单位是"度×100"。

| 你设的 `--roll` | rcCommand | 目标倾角 |
| --- | --- | --- |
| 75（默认） | ±75 | **±15 度** |
| 150 | ±150 | ±30 度 |
| 40 | ±40 | ±8 度（很温和） |

> 30 度倾角已经相当激进（会快速加速侧移）。**建议从默认 75 开始，甚至先用 40。**

## 3. ⚠ 必须核对的两件事（上机前）

### 3.1 RX 引脚的复用号

遥控器原来的串口是**只发不收**的：

- `bsp_uart.c:42`：`sUartxHandle.Init.Mode = UART_MODE_TX;` ← 只有 TX
- `bsp_uart.c:58-63`：RX 引脚的配置**整段被注释掉**

所以遥控器出厂状态**收不到任何串口数据**。我在 `rc_pc_ctrl.c` 里补上了：

```c
gimbal.Pin       = GPIO_PIN_2;
gimbal.Alternate = GPIO_AF4_USART2;   // ← 这个复用号要你核对
```

`GPIO_AF4_USART2` 是 **PA3 作 USART2_RX** 时用的值（见遥控器工程
`drivers/bsp/py32f030xx_Start_Kit.h:131`）。

**但 PB2 能否复用成 USART2_RX，我无法确认。** 请查：

1. PY32F030 datasheet 的**引脚复用表**里 PB2 那一行有没有 `USART2_RX`
2. 或者看遥控器工程的 `py32f0xx_hal_gpio_ex.h` 里有没有 `GPIO_AFx_USART2`
   对应的 PB2 说明

**如果复用号不对**，症状是：`rc_pc_frames_ok` 一直是 0（用调试器看这个变量）。
改 `rc_pc_ctrl.c` 里那一行的 AF 号即可。

### 3.2 PB2 有没有引出来

遥控器的 `UARTx_RX_PIN = GPIO_PIN_2`、`UARTx_RX_PORT = GPIOB`（`bsp_uart.c:18-19`），
说明设计上 PB2 是预留的 RX。但要**看板子上这个焊盘是否可用**。

## 4. 接线

| 遥控器 | → USB-TTL |
| --- | --- |
| **PB2**（USART2_RX） | → 转接器的 **TXD** |
| **GND** | → 转接器的 **GND** |

> 注意方向：这次是**电脑发、遥控器收**，所以接转接器的 **TXD**（不是 RXD）。
> 如果你同时想看遥测（上一轮做的功能），就要再接一根 PB… 的 TX 线，
> 那时是接 RXD。两个方向可以并存。

> ⚠ **用 3.3V 电平的转接器**。PY32F030 是 3.3V 芯片。

## 6. 电脑侧操作

```powershell
# 不需要装任何东西就能看协议（pyserial 是懒加载的）
python build-gcc\tools\pc_keycontrol.py --dry-run

# 实际发送（拆桨叶！）
python build-gcc\tools\pc_keycontrol.py COM3

# 调参数（都是可选）
python build-gcc\tools\pc_keycontrol.py COM3 --roll 40 --climb 50 --descend 200
```

**参数说明**：

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `--roll` / `--pitch` | 75 | WASD 的倾角档位（75 → 15 度） |
| `--yaw` | 150 | QE 的偏航角速度档位 |
| `--climb` | 150 | 上升档位（速度 = 档位×4） |
| `--descend` | 300 | 下降档位（速度 = -档位） |
| `--hz` | 50 | 发送频率（与遥控器循环一致） |
| `--dry-run` | — | 不打开串口，只显示会发什么 |

### 安全机制（都在代码里）

| 机制 | 行为 |
| --- | --- |
| **斜坡限速** | 每帧最多变化 12（`RAMP`），避免键盘一按就是满舵 |
| **松手回中** | 用"最后一次按键时间"判断松开（键盘自动重复约 30Hz，超过 120ms 没重复就认为松手） |
| **超时交还** | 遥控器 200ms 收不到合法帧 → 自动切回物理摇杆 |
| **总开关位** | 帧里 `engage` 位；不发这个位，遥控器永远用物理摇杆 |
| **急停** | 按 **B** 立刻回中并退出接管 |
| **退出时回中** | Ctrl+C 退出前会发 10 帧回中 + `engage=0` |
| **不提供解锁** | 程序故意不发解锁指令，起飞必须你手动按遥控器 |

## 7. 上机步骤（**别跳步**）

| 步 | 做什么 | 预期 | 不对怎么办 |
| --- | --- | --- | --- |
| 1 | `pc_keycontrol.py --dry-run` | 屏幕上滚动显示帧与轴值 | 没显示 → 看 Python 报错 |
| 2 | **拆掉桨叶**，接好 PB2/GND，烧录遥控器 | — | — |
| 3 | 打开遥控器与飞机，跑 `pc_keycontrol.py COM3` | 程序显示"正在发送" | 串口打不开 → 查串口号/占用 |
| 4 | 按键，看程序显示的轴值变化 | 空格→油门1700，W→俯仰1575… | 值不变 → 键盘读取问题 |
| 5 | **看电机反应**（桨已拆） | 空格→四个电机加速；W→前两个/后两个差速 | 完全没反应 → **查 `rc_pc_frames_ok` 是否为 0**（§3.1） |
| 6 | 方向核对 | W 应该是**前倾**（前两个电机减速？取决于机架朝向，**以你的机架为准**） | 反了 → 把 `--pitch` 用负值，或在程序里调换 W/S |
| 7 | 拔掉 USB 线 | **遥控器立刻恢复物理摇杆** | 没恢复 → 超时逻辑有问题，**立即停止** |
| 8 | 装桨，系留（绳子拴住），小油门试 | 松手能保高 | — |
| 9 | 逐步加大幅度 | — | — |

> **第 6 步特别重要**：方向反了会导致飞机朝你预料的反方向飞。
> 请务必在**拆桨**状态下把四个方向 + 两个旋转都核对一遍。

## 8. 已知限制

| 限制 | 说明 |
| --- | --- |
| **WASD 不会自动停住** | 飞控只有姿态环，没有水平位置环（没有 GPS/光流）。松手后飞机会带着速度继续飘，**需要你手动反打修正** |
| **偏航没有绝对航向** | 没有磁力计，`angle[2]` 被强制为 0（`pid.c:247`）。QE 控制的是**旋转速度**，不是"转到某个角度" |
| **键盘手感不如摇杆** | 键盘是离散输入 + 系统按键延迟（几十毫秒）。做"按键控制"够，精细飞行勉强 |
| **延迟约 20ms** | 遥控器 50Hz 循环（TIM16 每 20ms 触发一次发包），所以指令延迟约 20ms + 射频时间 |
| **只在正常模式可用** | CRSF 模式（400000 波特）下遥控器会进入自己的 `while(1)`，那一路不做键盘控制 |
